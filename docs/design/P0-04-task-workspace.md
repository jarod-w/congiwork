## 1. 背景与目标

计划 §4.3 明确指出这是原方案中被低估的部分：**「在 Workflow Mining 有意义之前，必须先有一个让用户愿意每天用来派活的界面」，「这里才是积累真实工作数据的入口」**。

同时它承担 §10.2 的冷启动职责：用「单次任务代劳」而非「长期学习」作为获客钩子，用户第一次使用就要看到价值。

目标：

- **G1** 零安装、零授权即可完成第一个有价值的任务（信任爬坡 L1）。
- **G2** 执行过程可见、可干预、可理解——把 Agent 的黑盒变成可审查的工作过程，这是从 L1 走向 L3 的前提。
- **G3** 从任务自然沉淀出记忆和 Skill，而不是让用户额外去别的页面配置。

非目标：

- 不做团队协作、共享工作区（Phase 3）。
- 不做富文本文档编辑器（结果产物用预览 + 下载，不做在线编辑）。
- 不做移动端适配（Phase 1 仅桌面浏览器宽度）。

## 3. 信息架构

```text
┌───────────┬──────────────────────────────────────┬──────────────────┐
│           │                                      │                  │
│  任务列表  │            对话 + 时间线              │   上下文面板      │
│           │                                      │  （可折叠）       │
│  ・进行中  │  用户消息                             │                  │
│  ・今天    │  ─────────────────────────           │  本次用到：       │
│  ・更早    │  ▸ 计划：3 步                         │   记忆 3 条 ▸    │
│           │  ▸ 读取上传文件 (0.4s) ✓              │   技能 1 个 ▸    │
│  + 新任务  │  ▸ 检索 Gmail (1.2s) ✓                │   工具 2 个 ▸    │
│           │  ⏸ 待你确认：发送 3 封邮件             │                  │
│           │     [预览] [批准][修改][拒绝]          │  产物：          │
│           │  ─────────────────────────           │   周报.xlsx ▸    │
│           │  AI 输出（流式）…                     │                  │
│           │                                      │                  │
│           │  [输入框] 📎 ⚙                        │                  │
└───────────┴──────────────────────────────────────┴──────────────────┘
```

三栏布局的理由：中间栏承载「做什么」，右栏承载「凭什么」。右栏不是附属信息——它是把「AI 在用我的数据」这件事变得可查证的地方，是 §5 信任爬坡从 L2 走向 L3 的界面基础。默认展开，用户可折叠。

## 4. 关键交互设计

### 4.1 时间线与对话的融合（WS-2 / WS-3）

不做「对话在上、日志在下」的分离布局。执行步骤**内联在对话流中**，作为可折叠的紧凑条目：

- 默认折叠为一行：`▸ 检索 Gmail 中"季度报告"相关邮件 · 找到 8 封 · 1.2s ✓`
- 展开显示：调用的工具、脱敏后的参数摘要、结果摘要、用到的权限 Scope。
- 失败步骤默认展开，且用错误分类的可读文案（见 `P0-03` §9）。

理由：分离布局会让用户忽略执行细节，而执行细节正是建立「它确实在认真做事」印象的来源。

### 4.2 审批卡片（WS-4）

```text
┌─────────────────────────────────────────────┐
│ ⏸ 需要你确认：发送邮件（不可撤销）             │
├─────────────────────────────────────────────┤
│  收件人：3 人  ▾                              │
│  主题：Q3 渠道复盘 — 请查收                    │
│  ┌───────────────────────────────────────┐  │
│  │ Hi Alex,                              │  │
│  │ 附件是 Q3 各渠道的转化数据…            │  │  ← 真实预览，可就地编辑
│  └───────────────────────────────────────┘  │
│  📎 Q3渠道复盘.xlsx                          │
├─────────────────────────────────────────────┤
│ [批准发送] [修改后发送] [跳过这步] [取消任务]  │
│ □ 以后发邮件不用问我   ← irreversible 时禁用   │
└─────────────────────────────────────────────┘
```

设计约束：

- **预览就是产物本身**，不是参数 JSON。
- **可就地编辑**，编辑后的内容直接生效并记入 `user_edits`。
- 「跳过这步」与「取消任务」分开——用户常常只是不想做这一步。
- 批量场景（发 5 封邮件）合并为一张卡片，可逐条展开、逐条取消。

### 4.3 内联授权（WS-10）

任务执行中需要未授权能力时，**不跳转到设置页**：

```text
▸ 我需要读取你的 Gmail 才能继续
  这会做什么：搜索并读取邮件内容，用于本次任务
  不会做什么：不会发送、不会删除、不会保存邮件正文
  [连接 Gmail（只读）]  [跳过，我自己粘贴内容]
```

「跳过」必须是一个真实可用的路径——这是 `00-conventions.md` §5 自愿性检查项的界面体现。授权完成后任务从中断点原地继续，不需要重新发起。

### 4.4 顺手沉淀（WS-7）

任务结束后在结果下方追加一张轻量卡片，**最多 3 条候选**，可整体忽略：

```text
┌─────────────────────────────────────────┐
│ 顺手记一下？                              │
│ ✓ 你们 Q3 的主推渠道是企微和小红书         │
│ ✓ 报告偏好按渠道拆分，不按地区              │
│ □ 把这个流程存为技能「季度渠道复盘」        │
│           [都记下]  [不用了]              │
└─────────────────────────────────────────┘
```

- 记忆候选来自 `P0-02` §5.1 通道 ②，画像候选来自 `P0-01` §5.3。
- 「存为技能」跳到 `P0-06` 的 Skill 创建流程，预填本次任务的步骤。
- 卡片可以直接忽略，不阻塞、不弹窗、不再次提醒。

### 4.5 冷启动空状态（WS-9）

新用户首次进入（或无任务时）展示 4–6 个**高价值、零授权**的任务模板，直接对应计划 §10.2 的典型场景：

| 模板 | 输入 | 所需授权 |
|---|---|---|
| 把这份表格整理成周报 | 上传 xlsx/csv | 无 |
| 根据这些要点起草一封邮件 | 粘贴要点 | 无 |
| 把这份长文档提炼成决策摘要 | 上传 pdf/docx | 无 |
| 把这堆客户反馈分类打标 | 上传/粘贴 | 无 |
| 按我的风格改写这段内容 | 粘贴 | 无 |

**全部模板都不需要任何授权**——这是刻意的：第一次使用必须证明价值，之后才谈授权。

## 5. 前端技术方案

| 项 | 选择 | 说明 |
|---|---|---|
| 框架 | React 18 + TypeScript + Vite | |
| 样式 | TailwindCSS + shadcn/ui | 计划 §7.3 |
| 服务端状态 | TanStack Query | 任务列表、记忆、技能等 |
| 客户端状态 | Zustand | 当前会话、面板折叠等 UI 状态 |
| 流式 | 原生 `EventSource` + 自研重连层 | 携带 `from_seq` 补发，见 `P0-03` §10 |
| Markdown | react-markdown + rehype 白名单 | 禁止原始 HTML，防注入 |
| 表格预览 | 轻量虚拟滚动表格 | 支持 10 万行 xlsx 预览 |
| 复用 | 核心组件下沉到 `packages/shared-ui` | 桌面端直接复用，见 `P0-08` |

**共享组件边界**：`shared-ui` 只放与运行环境无关的展示组件（消息气泡、时间线、审批卡、产物预览）。所有网络请求、路由、存储通过 props / context 注入，由 web 或 desktop 各自提供实现——否则桌面端复用会被 web 的假设污染。

### 5.1 流式渲染的性能约束

长输出场景下每个 `message.delta` 都触发 React 重渲染会卡顿。做法：

- delta 累积在 ref 中，用 `requestAnimationFrame` 节流，最多 60fps 提交一次。
- 已完成的消息用 `React.memo` 冻结，不参与后续渲染。
- 时间线条目超过 50 条时虚拟滚动。

## 7. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 首次任务失败导致用户直接流失 | 极高 | 模板任务用最稳的能力（纯文本+文件处理，不依赖外部工具）；失败时给出可操作的下一步而非道歉 |
| 时间线信息过载，用户看不懂 | 中 | 步骤标题必须是自然语言（由 LLM 生成，非工具名）；默认折叠；细节按需展开 |
| 审批太频繁导致弃用 | 高 | 见 `P0-03` §11；工作台侧提供「本次任务内批量批准」 |
| 右栏透明面板被当成没用的信息被折叠，信任建设失效 | 中 | 首次出现时高亮引导一次；当次任务用到记忆时在消息内联标注「基于你之前说的…」并链到右栏 |
| 流式渲染卡顿 | 中 | §5.1 的三条约束，作为性能验收项 |

## 8. 验收标准

1. 新用户从落地页到拿到第一个任务结果，全程无需任何授权，中位耗时 ≤ 5 分钟。
2. 首 token 延迟 P95 ≤ 2s；1 万字输出全程无掉帧（Chrome Performance 面板 ≥ 50fps）。
3. 断网 30s 后恢复，对话与时间线状态完整无重复。
4. 任务中途触发授权引导，授权后任务原地继续，不丢失已完成步骤。
5. 用户可在结果页 3 次点击内完成「把这次流程存为 Skill」。
6. 计划 §6 Phase 1 验证目标：用户自发创建 ≥3 个手动 Skill 并复用——工作台侧需提供埋点支撑该指标统计。

## 9. 埋点（服务于 Phase 1 验证目标）

计划 §6 的退出条件需要数据支撑，工作台是主要采集点。以下埋点是**产品自身运营数据**，不属于用户工作内容采集，无需 `telemetry` Scope（但仍需在隐私政策中说明）：

| 事件 | 用途 |
|---|---|
| `task_created` / `task_finished{status}` | 任务成功率、活跃度 |
| `template_used{template_id}` | 冷启动钩子有效性 |
| `authorization_prompted{scope}` / `authorization_granted{scope}` | **信任爬坡各层转化率** ← 最关键指标 |
| `approval_resolved{action}` | 审批体验、始终允许的采纳率 |
| `memory_candidate_accepted{count,total}` | 记忆质量 |
| `skill_created{source}` / `skill_reused{skill_id}` | Phase 1 退出条件之一 |
| `context_panel_expanded` | 透明面板是否被使用 |
