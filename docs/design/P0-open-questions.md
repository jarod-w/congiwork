> **当前口径（2026-08-18 收盘）**：A9 已把周期改为 **3.5 个月**（有效容量约 285–304 人日）。当日两次相反方向的调整基本相抵——连接器改定 **+5d**（`P0-05`）、B5 只做 Graph **−6d**（`P0-08`），净 −1d，需求落在 **302 人日**。

**结论：A5 已定为 5 人，但它是按单平台 255 人日给出的建议；A4 选双平台后容量不够。缺口的处理方式见 §1.2 A9（已定案：周期放到 3.5 个月）与 A10（已定案：不砍范围）。**

### A4 桌面端 Phase 1 覆盖单平台还是双平台？

| 项 | 内容 |
|---|---|
| 背景 | P0-08 待决问题 1 |
| **建议** | **单平台，优先 Windows** |
| 理由 | Excel COM 是所有 L1 路径中最成熟可靠的；macOS 的 AppleScript 对 Excel 覆盖明显弱，硬上会拉低成功率、危及 ≥90% 的验收门槛。分平台上线优于降低成功率标准 |
| 代价 | 双平台会让 P0-08 的 68 人日接近翻倍 |
| 影响 | P0-08 全文 |
| **结论** | **已确认（2026-08-17）：双平台（Windows + macOS）。** 回写见 `P0-08` §2.1 / §4.3 / §8.1 / §8.3 / §13 |
| 落实方式 | 原建议单平台的顾虑（macOS AppleScript 对 Excel 覆盖弱）不靠降标准解决，而是**换主路径**：macOS 上 Excel 以 openpyxl 文件态为主，AppleScript 只做轻动作，覆盖不到的动作（透视表、图表）明确标注不支持。见 `P0-08` §4.3 |
| 必须的连带改动 | **门禁粒度从「按适配器」细化为「按适配器 × 平台」**。否则 Windows 96% 与 macOS 82% 会平均成「89% 或 91%」，两种结论都是错的。白名单变成一张 3×2 矩阵，允许「macOS 上邮件不上线」这种结果。见 `P0-08` §8.3 |
| **重估代价** | P0-08 从 **78 人日**（68d 里程碑 + 10d 缓冲）涨到 **113 人日**（98d + 15d 缓冲），逐项账见 `P0-08` §13。P0 总量从 265 涨到 **约 300 人日** |

### A10 首批连接器改定后的 5 人日增量怎么吸收？（2026-08-18 新增，阻塞型）

| 项 | 内容 |
|---|---|
| 背景 | 决策者把首批连接器改为 Gmail + Calendar + Notion + GitHub（4 个），`P0-05` 从 27 涨到 32 人日（逐项账见 `P0-05` §2.1.3）。总需求 303 → 308 人日（**同日 B5 又省 6d，最终落在 302**，见下方「容量部分」行）|
| 现状 | A9 定的 3.5 个月 × 5 人 → 有效容量 **304**（20% 损耗）/ **285**（25% 损耗）。原本余量 1 人日，现在**乐观假设缺口 4 人日，保守假设缺口 23 人日** |

**建议：不为这 5 人日砍范围。但这道题的重点不在 5 人日。**

先说 5 人日：它占 308 的 1.3%，低于任何一个里程碑估算本身的误差。为 1.3% 现在就砍功能是过度反应，会在还没有任何实测数据时先损失产品完整性。A9.1 已经建好了触发式预案（macOS 只上 Excel 省 18d、B8 省 3d、访谈缩轮省 3d，合计 24d），足以覆盖保守假设下的 23 人日缺口——机制是现成的，不需要新建。

**真正变了的是风险的性质，不是风险的大小：**

| | 改定前 | 改定后 |
|---|---|---|
| 缺口来源 | 内部工作量估算 | 内部工作量估算 **+ 一个外部不可控的审核周期** |
| 能否靠加人/加班压缩 | 能 | **CASA 那部分不能** |
| 最坏情况 | 晚交付几天 | **Gmail 整个不能上线** |

加人加班压不动 Google 的评估队列。所以 A10 的正确答案不是「去哪找 5 人日」，而是**把 CASA 从关键路径上挪下来**。三条配套动作：

1. **M3 按「Calendar + Notion 先做，Gmail 最后做」拆**（已写入 `P0-05` §11）。这样 G2 触发降级预案时，受影响的是 M3 的尾部而不是整个里程碑。
2. **容量复核从「第 1 个月末」提前到「第 3 周末」**，与 `P0-05` §2.1.1 的 G1 检查点合并成一次会。理由：改定后前期的不确定性显著高于改定前，第 1 个月末才看第一眼太晚。A9.1 原定的第 1 个月末复核保留，变成第二次。
3. **两套 Gmail scope 清单在 M0 就备好**，不等到 G2（见 `P0-05` §2.1.1）。
